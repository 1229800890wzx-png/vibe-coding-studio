# 项目实战与教学质量方案

版本：2026-09-15 · 教研实施建议，待试教验证。本文承接“基础→使用→实战”三阶段、每阶段12次课的完整路径；不是已经开班、聘任导师或授予认证的声明。网站现有11组互动内容可作导入与复习，不能替代完整教案或作为学员完成记录。

## 一、项目阶段：用12次课完成一件作品

第25–36课围绕一个 capstone（综合作品）持续推进，不安排12个彼此割裂的项目。进入前，学生需能说明变量和条件，完成一次“小步修改→运行→检查→保存”，并分清模型回答与工具返回。未达到者先补对应技能，再进入匹配范围的项目。

标准课90分钟：回顾10分钟、示范15分钟、第一轮实践20分钟、休息10分钟、第二轮实践20分钟、演示互评10分钟、退出卡5分钟，共80分钟教学。7–9岁另设75分钟版本，含10分钟休息、65分钟教学，增加活动切换并缩小功能范围；不得把较短课直接标作90分钟等效课时。必要时增加课次，排课与收费需另行明确。

默认一人一份作品，可两人结对试用、轮换操作；共同作品必须有各自的修改、解释和迁移证据。第一课锁定“必须完成、可以加强、暂不做”三张清单，导师按前置能力调整任务，不只按年龄分层。

| 实战课／总课序 | 本课里程碑与可见交付 | 导师检查与未达处理 |
| --- | --- | --- |
| 1／25 选题与用户 | 一页任务书：给谁用、核心规则、3条验收条件、范围与预算 | 学生讲出一个真实使用场景；过大选题当堂收缩 |
| 2／26 纸上原型 | 故事板／线框图、输入输出表、异常场景 | 同伴按图走通流程；说不清的按钮先补规则 |
| 3／27 技术小实验 | 单独验证最难的一条规则；保存初始版本 | 每人说明输入如何改变结果；不成立则换实现方案 |
| 4／28 最小闭环 | 从开始到结果再重来的可运行版本 | 不依赖导师临时改代码即可演示；未通过暂停装饰 |
| 5／29 核心功能一 | 一项关键扩展、修改前后差异和检查记录 | 先预测再运行；检查变量、条件或函数的作用 |
| 6／30 核心功能二 | 完成已约定功能；中期版本与个人口述 | 逐人检查理解，不会解释的部分缩小后重做 |
| 7／31 测试与调试 | 正常、边界、错误输入用例；一个修复前后对照 | 先复现再定位，修复后重测；保留失败记录 |
| 8／32 用户试用 | 同伴完成指定任务；记录卡点与改进优先级 | 区分观察、缺陷和个人偏好；每人选一项有证据的改进 |
| 9／33 体验与表达 | 改进可读性、操作反馈、键盘／触控体验 | 复测核心功能；低龄聚焦文字、按钮、声音可控 |
| 10／34 方法复用 | 一份检查清单／Skill草稿；一次不同任务上的试用 | 说明适用条件和修改项；MCP仅在有真实需求时选用 |
| 11／35 发布候选 | 完整项目包、运行说明、素材来源、AI帮助说明 | 在另一台约定设备按说明启动；阻断错误必须修复 |
| 12／36 展示与答辩 | 最终演示、个人解释、现场迁移、下一步计划 | 评分并过三道关；未通过给具体补修单和复测日期 |

每课留下四项最小证据：本次目标、关键改动、实际测试结果、帮助级别。低龄可用录音、截图与教师代记；不要求上传完整聊天记录。第6、11课设置范围冻结点，未完成核心功能时先取消加强项。

## 二、四个可选项目方向

“加强版”是通过最小交付后的可选任务，不是所有年龄的统一结课承诺。三年龄组分别采用图形化／可视化规则、图形化向文本过渡、文本代码与模块设计；能满足同样目标的学生可跨层选任务。

### A. 原创规则小游戏：星球快递站

玩家选择路线运送包裹，燃料与得分随操作变化。学生设计自己的规则、角色和关卡，避免照搬商业角色与现成关卡。

| 项目要素 | 设计与验收 |
| --- | --- |
| 最小交付 | 一种操作、一个资源变量、成功与失败条件、说明和重开；一局可完整结束 |
| 加强版 | 多关卡、难度曲线、随机事件或可解释的路线策略，选其中一项 |
| 年龄适配 | 7–9岁：按钮和图形积木、单关固定地图；10–12岁：循环生成任务、计时与关卡；13–18岁：状态机、模块化规则、固定随机种子用于复测 |
| 编程＋AI映射 | 事件、变量、条件、循环、状态；让AI提出规则冲突，再由学生用反例验证；对一项功能写清验收条件并检查代码差异 |
| 测试验收 | 资源为0、刚好够用、连续操作、失败后重开；重开不残留旧分数，同一包裹不重复计分 |
| 预算／联网边界 | 基础版使用本地素材与浏览器／离线编辑器，无付费API；联网排行榜仅高龄选修，用匿名测试数据，不接支付；断网回退本机记录 |

### B. 互动故事：会记住选择的森林

选择帮助哪位角色会改变后续对话和结局，让孩子体验“状态影响叙事”，而不只把AI生成文字粘贴成多页幻灯片。

| 项目要素 | 设计与验收 |
| --- | --- |
| 最小交付 | 至少3个场景、2个结局、一项影响后续的选择状态、重新开始入口 |
| 加强版 | 背包道具、隐藏分支或多语言切换，选一项；实时生成对话不是必需功能 |
| 年龄适配 | 7–9岁：绘图／配音、图形分支和一个旗标；10–12岁：条件组合与场景数据表；13–18岁：数据驱动叙事、状态保存和内容校验 |
| 编程＋AI映射 | 顺序、分支、布尔值、列表／对象、输入输出；比较不同上下文的续写，检查前后矛盾；标注AI协助文字与素材 |
| 测试验收 | 遍历所有设计路径，结局均可到达；无无出口场景；持有／未持有道具都符合规则，重开清除选择 |
| 预算／联网边界 | 自绘、授权素材及预生成文本可离线运行，生成额度由机构预设；实时模型仅受管教学扩展，失败使用固定对话，不收集儿童自由聊天 |

### C. 高级作品网站：我的微型博物馆

以孩子的收藏、自然观察或原创作品为主题，做信息清楚、风格一致、可交互的网站。“高级”体现在内容组织和使用体验，不能只用动画数量或生成速度衡量。

基线采用原生HTML/CSS/JavaScript与已验证的简单页面模板，列表和详情可在同一页面切换。入口诊断四项：识别标题、图片等标签结构；修改一处样式并说明影响；预测点击事件结果；从数组／列表中增加或筛选一件展品。低龄可结合卡片和模板口述，分别记录“理解规则”与“独立修改代码”的能力，不能互相替代。

缺少选定任务所需前置时，可按诊断安排2–4次桥接课的初步方案，教后复测，或改选匹配项目；桥接课总课次另计，不能挤入既定36课并宣称覆盖。36课不承诺所有学生独立搭建全部网站技术。模板包须列出教师预置的结构、样式和交互，作品记录另外列明孩子实际修改范围。

| 项目要素 | 设计与验收 |
| --- | --- |
| 最小交付 | 首页、至少3件展品的列表与详情、一个筛选交互、来源说明；手机与电脑均可使用 |
| 加强版 | 搜索或主题切换，选一项；组件、路由、异步接口仅在对应能力已具备后选修；登录、数据库与后台另列进阶课 |
| 年龄适配 | 7–9岁：使用已预置交互的模板，学生选择展品、安排内容、修改颜色与一条筛选规则，逐项标明提示；10–12岁：模板内HTML/CSS、数组渲染与事件；13–18岁：原生JS函数、数据结构和DOM交互，按诊断逐步减少模板 |
| 编程＋AI映射 | 数据与展示分离、函数、条件、数组与DOM；从草图说明交互，让AI小步改页，阅读相关代码；用检查清单或Skill复查页面 |
| 测试验收 | 链接与返回有效；筛选无结果有反馈；320px与桌面宽度无水平溢出；键盘可到达交互控件，图片有合适说明 |
| 预算／联网边界 | 本地预览即可结课，无域名与主机购买要求；公开托管由机构另审素材、个人信息和费用；断网使用打包站点与本地图片 |

### D. 实用工具：书包与活动小管家

围绕整理书包、安排社团物料等小任务，做能添加、检查、保存与恢复的清单；选择不会承担真实财务、医疗或安全决策的小场景。

| 项目要素 | 设计与验收 |
| --- | --- |
| 最小交付 | 添加项目、标记完成、删除前确认或可撤销、空列表反馈；核心操作可重复执行 |
| 加强版 | 本地保存、筛选统计、JSON导入导出，按能力选一项 |
| 年龄适配 | 7–9岁：图标清单、固定选项与计数；10–12岁：自定义项目、数组与本地保存；13–18岁：校验、模块与存储异常处理 |
| 编程＋AI映射 | 列表、函数、增删改查、输入校验；把生活描述变为规则；高龄可在隔离环境经MCP读取模拟物料清单，说明请求、返回与权限 |
| 测试验收 | 空白、重复和过长输入；最后一项删除、连续点击；选择保存功能者重载不丢数据，损坏数据有可理解反馈 |
| 预算／联网边界 | 默认本机虚构数据、零外部调用；真实同步和MCP非结课条件，不接学校真实账号；断网用JSON样例和模拟返回，明确标为模拟 |

所有方向先满足零付费外部调用的基线。确需生成图片或调用模型时，开课前由机构核查账号、年龄、所在地区和实际使用条件，并记录工具实际计价、班级额度、单次上限与总额，达到80%先检查余量，到上限停止；不让学生自行开通无限计费。没有符合条件的在线工具时，采用导师准备的样例、合法离线环境与模拟调用。断网替代仍须完成规则、测试和解释，不把预设回答说成实时AI输出。网站现有AI／MCP仅为教学模拟预览，不能作为已具备真实服务或授课平台的证明。

### Minecraft MOD：另设进阶支线

仅向已具备Java语法、类与对象、构建及日志阅读能力的学生开放，通常从13–18岁能力组评估进入；10–12岁须通过同样前测，7–9岁先用原创积木／网页模拟机制。兴趣不能替代前置能力。Fabric开发文档明确要求Java与面向对象基础。[Fabric开发前置](https://docs.fabricmc.net/develop/)

最低范围限定为“一个原创物品＋一种可测试交互／配方”，加强版才考虑小机制组合；不承诺任意MOD、大型整合包或复刻商业IP。使用合法可用的Minecraft Java版环境，预先锁定游戏、JDK、Loader、API、构建插件及模板版本，并由导师在学生设备上验证；JDK要求随游戏版本变化，不能沿用过时安装口令。[Fabric环境设置](https://docs.fabricmc.net/develop/getting-started/setting-up)

验收包含干净实例启动、物品注册与资源加载、重复操作、保存重进、移除MOD后的已知限制说明。软件与设备成本另列，不计入基础项目默认预算；依赖提前缓存，断网不能构建时改做规则模拟并标明未完成MOD交付。需要补Java或环境课时，另排准备单元，不挤占12次作品阶段。

## 三、100分评价与三道必过关

评价关注问题定义、创作、测试和迭代等实践；这些方向与[CSTA 2026官方框架](https://csteachers.org/pk12standards/view/)中的相关实践一致。以下分值、门槛和课次是本项目的原创教学建议，未经过CSTA认证。

| 维度 | 分值 | 高质量证据与评分锚点 |
| --- | ---: | --- |
| 目标与规则 | 10 | 满分：对象、范围与验收可检查；5分：需提示补全；0分：无法说出用途 |
| 功能与可运行性 | 25 | 满分：约定核心功能全通、可复现启动；15分：可完成主流程但有非阻断缺陷；0分：无法启动或完成主流程 |
| 编程理解 | 20 | 满分：独立预测、追踪和修改关键逻辑；10分：提示后解释局部；0分：复述AI文字且不能指认对应规则 |
| 测试与修复 | 15 | 满分：正常／边界／异常证据与修复回归；8分：只测正常流程；0分：无实际运行证据 |
| AI协作与判断 | 10 | 满分：清楚任务、检查生成结果、解释采纳／拒绝与工具边界；5分：记录帮助但检查不足；0分：把输出当事实且无法核验 |
| 体验与原创表达 | 10 | 满分：内容一致、操作清楚、素材来源可追溯；5分：可用但有明确体验障碍；0分：内容无法辨认或来源无法说明 |
| 过程、复用与表达 | 10 | 满分：版本、帮助记录、方法适用条件与现场演示完整；5分：过程不完整；0分：仅交成品 |

按证据在锚点间给整数分，7–9岁可用图形与口述，13–18岁要求代码追踪与书面测试；按选题时约定的年龄／能力范围评分，不因增加复杂功能自动加分。70分为建议达标线，85分为高质量；**无论总分多少，以下三关均须通过**：

1. **可运行关**：另一名教师按说明从干净副本启动，完成全部核心验收；不存在阻断主流程的错误。学生能指出启动入口，必要环境支持须记录。
2. **理解关**：逐人抽取两条关键规则，正确预测各一个新输入结果，并说明输入、状态与输出关系；至少定位一次错误原因。教师可读题，不提供解法。
3. **迁移关**：现场关闭AI，在15–20分钟内完成一个未练过但同层级的小修改并验证，如变更门槛、增加一个结局条件或过滤规则。允许自己的规则卡、语法表与图形工具；不允许同伴或教师给答案，合理学习支持另记。

AI帮助按“独立完成／经提问提示／AI或教师给出局部方案／他人完成后复现”记录。标注AI帮助体现诚实，**不等于独立掌握**；团队总分不能替代个人关卡。低龄阅读或操作支持与概念提示分开记录，避免把打字速度计作编程能力。

未达标报告写成“缺哪项证据→练哪一种能力→怎样复测”。在7日内安排15–30分钟小组补修，先用更小例子重建概念，再换题复测；需要更多时间可延后，不能靠反复背同一道答案通过。保留初测与复测结果；仍未通过记为“在支持下完成／继续学习”，调整后续范围，不写“独立掌握”。

## 四、小班教学的执行标准

以下是试运营配置建议，不代表已经聘任人员；师资应以真实履历、样课和作品审查核实，不以院校校徽或未经核验的头衔代替教学证据。

| 年龄能力组 | 建议班额与现场配置 | 主要支持任务 |
| --- | --- | --- |
| 7–9岁 | 4–6人，1主讲＋1助教 | 口述、鼠标与阅读支持；短回合轮换；逐人确认规则 |
| 10–12岁 | 6人，1主讲＋1助教 | 任务拆解、从积木到文本、及时发现“复制但不懂” |
| 13–18岁 | 6–8人，1主讲＋1助教 | 项目差异较大时分组诊断、代码评阅、个人答辩 |

主讲负责概念讲解、节奏、分层与个人评价；助教负责设备、观察记录、排障和即时提示，不替学生完成核心逻辑。两人都须在试讲中展示如何把帮助逐步撤去。班额超过建议上限应拆班或增加能独立带组的教师，再经试教确认。

拟设教研负责人、儿童教学顾问、编程工程顾问与AI研究顾问，可由合格人员兼任但职责须留痕：教研负责人维护目标与评价；儿童教学顾问审阅负荷、提问和差异支持；工程顾问复核模板、测试与环境；AI研究顾问核对模型、Agent、Skill、MCP的能力边界与官方变化。顾问不代替一线带班教师。持续发展教师的内容知识和教学能力，也符合[CSTA教师标准的专业成长方向](https://csteachers.org/teacherstandards/)。

执行节奏如下：

- **开班前试教**：每年龄组用4–6名对应基础学生试教代表课，观察任务完成、独立解释、等待排障与挫败点；涉及观察记录需适当告知。出现核心环节普遍超时或理解断层，先改任务再排班，不能用“作品好看”代替通过。
- **双师备课**：每周45–60分钟，两人各自跑通样例与故障版，演练正常、断网、额度耗尽方案；确认何时提示、何时停止加功能。
- **过程评阅**：每课逐人至少一次“预测—运行—解释”；第6、11课双师复核关键关卡。抽查至少20%作品双人评分，差异超过10分或关卡结论不同必须讨论证据，统一后再发报告。
- **家长反馈**：每4课发一页记录，包含本期目标、一项学生原话／操作证据、帮助程度及下步练习；第6、12课另反馈个人关卡。默认使用班内作品展示，公开发布需单独落实许可。
- **教案素材包**：每课交付目标与前测、分钟安排、三层任务卡、示范源文件、故障样例、素材来源清单、预期与边界测试、AI提示与核验例、离线包、教师提问、退出卡及评分记录模板。
- **版本更新**：稳定概念与易变工具说明分册维护；每月检查工具官方文档，班前复测环境。变更记录包含日期、来源、适用年龄、影响课次和回退方案；换模型或依赖先跑教学验收，学期中避免无必要迁移。按季度复盘个人关卡通过情况与补修原因，不把目标值写成已有成效。

## 五、重点课详案

### C04 最小闭环（总第28课）

**目标与前置**：学生用已有原型做通“开始→操作→结果→重来”，能解释一个状态变化。课前带C01任务书、C02流程图、C03技术实验与可恢复版本。双师准备三层起始文件、离线素材、测试卡和“重开未清零”故障样例；先在教学设备跑通。

| 分钟 | 学生任务与双师组织 |
| --- | --- |
| 0–10 | 各用一句话说核心操作与结果；主讲锁定本课范围，助教核对文件 |
| 10–25 | 主讲示范“三颗星开门”，先预测2／3／4颗的结果，再小步修改；学生指出变量和条件 |
| 25–45 | 学生实现自己作品的一条完整主流程；双师各巡半班，先问预期，再看代码／积木 |
| 45–55 | 离屏休息10分钟 |
| 55–75 | 增加重来／返回，依正常、边界、重置三类测试；保存通过版本和帮助记录 |
| 75–85 | 结对按操作卡试用，作者解释一次状态变化；双师核对未通过项 |
| 85–90 | 提交版本、三条测试结果与退出卡：“重来需要恢复哪些状态？” |

**分层与卡点**：7–9岁用积木／页面骨架，75分钟依次分配5、10、20、10、15、10、5分钟；10–12岁自行连接事件和变量；13–18岁提取状态重置函数。若忙于装饰，回到三张范围清单；若重复加分，追踪事件是否触发两次；若重开残留，列出所有状态逐项检查。教师只给下一步问题，AI修改仅在允许环境中小步进行并核验。

**验收**：学生亲自从初始状态走到结果并重来，正常、边界、重置测试均符合本课约定；能预测一个新输入并指认关键规则。不同选题将“重来”映射为故事返回起点、网站返回列表或工具恢复测试清单。未过者停止加强功能，带失败记录进入补修。

### C12 展示与答辩（总第36课）

**目标与前置**：完成个人理解、无AI迁移和表达评价。C11已由另一教师完成干净副本启动与核心验收；封存版本，本课迁移用副本，展示版若改动须重新验收。双师课前校准评分，备每人两条规则题、同层级迁移A／B卷、故障定位题、计时器、离线副本和个人记录表；助教须能独立按量规评价。

| 分钟 | 6–8人、两教师并行安排 |
| --- | --- |
| 0–10 | 核对封存版本，关闭AI，说明可用规则卡与禁用帮助；发放个人题 |
| 10–30 | 全班同时独立迁移20分钟：预测、修改、测试、提交；两教师观察并记录帮助，不给解法 |
| 30–40 | 离屏休息10分钟；提交物已冻结 |
| 40–60 | 两个口述站并行，各最多4人，每人5分钟：两规则各预测新输入并解释，另定位一个错误；候测者静默写反思 |
| 60–80 | 每人2分钟展示核心操作、AI帮助与一项选择理由；最多16分钟展示、4分钟切换 |
| 80–90 | 个人自评、反馈证据与下一步；双师标记已过／待复核，分歧课后复核再发结论 |

**低龄适配**：4–6人、75分钟按“准备5＋独立迁移20＋休息10＋双站口述15＋展示15＋反馈10”安排。每站最多3人、每人5分钟；题目用图形和口述，阅读支持单独记录，不压缩迁移时间。

**任务与卡点**：迁移只改一项同层级规则，如开门门槛、结局条件或过滤项，题目参数与练习不同。会背术语却不会追踪时，用具体输入提问，不暗示答案；超范围修改先按已提交证据评价。晚到、设备或软件故障不挤占他人时段，保留现场记录并另约完整20分钟迁移／个人口述；缺测不判通过。

**验收**：汇总C11可运行证据与本课两规则解释、故障定位、独立迁移结果；三关全部通过且总分达标才记达标。演示流畅、同伴鼓掌或AI帮助标注都不能替代个人证据；补修按缺口换题复测。
