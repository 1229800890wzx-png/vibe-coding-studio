# 教学实施表单

配套 [课程总方案](CURRICULUM.md)｜v1.0｜2026-09-15

以下为可复制使用的模板及原创教学示例。它们没有对应真实学员，填写示例不代表试教结果。学员使用班内编号即可，不在课程资料中记录不必要的个人信息。

## 表 1：单次课备课单

| 项目 | 需要填写的内容 |
| --- | --- |
| 课程版本／课次／路径 | 例如 v1.0 / A05 / 创作组 |
| 本节核心问题 | 一句话，只对应一个主要概念 |
| 前置任务 | 学生必须已经能完成什么；用什么题快速检查 |
| 理解目标 | 学生能预测和解释什么 |
| 操作目标 | 本节要亲手改变什么 |
| 最小交付 | 课内一定要完成的可检查产物 |
| 环境与材料 | 工具版本、起始文件、素材、网络／账号要求 |
| 流程 | 回顾、概念、引导、休息、独立任务、检查与收尾，时长合计 |
| 两个关键提问 | 先要求预测；再要求解释实际差异 |
| 预设错误 | 一种概念误解＋一种可复现程序错误 |
| 降阶／加深 | 降阶保留核心概念，加深不引入整套新工具 |
| 评价与复测 | 学到的证据是什么；没通过时换什么题再验证 |
| 故障备用 | 离线材料、已保存项目、真实调用与模拟的标识 |
| 课后修改 | 本次试教改变了什么、为什么 |

## 表 2：学生一页任务书

**作品名称：** ______　**学员编号：** ______　**版本：** ______

1. 谁会使用它？他/她想完成什么？
2. 第一版只完成哪一个主要任务？
3. 使用者会做哪三个动作？每个动作之后应该发生什么？
4. 必须遵守哪些规则？请写成能检查的条件。
5. 哪些功能这次先不做？
6. 我已经知道什么？需要学习或请导师帮助什么？
7. 我准备在哪一步使用 AI？怎样确认它的建议可用？
8. 我怎样向同学证明这个作品能正常使用？

### 填写示例：星光探险

- 使用者：想玩一局短游戏的同学。
- 第一版任务：收集星星，达到门槛后打开大门。
- 动作：开始、收集、重开；对应分数归零、加分、恢复初始状态。
- 规则：分数达到或超过门槛时开门；同一颗星星只记一次；重开清除上一局状态。
- 暂不制作：联网排行榜、登录、商店、多个大地图。
- AI 帮助：请它解释一段重复计分代码的可能原因；由自己先复现，再决定修改。
- 验收：检查门槛前、恰好门槛、超过门槛、重复触发、重开五种情况。

## 表 3：预测—运行—解释记录

| 测试编号 | 输入／操作 | 运行前预测 | 实际结果 | 是否符合 | 如果不同，下一步检查什么 |
| --- | --- | --- | --- | --- | --- |
| T01 | 门槛 3，当前 2 颗星 | 门关闭 | 待运行 | 待判定 | 条件符号与计数值 |
| T02 | 门槛 3，当前 3 颗星 | 门打开 | 待运行 | 待判定 | 是否误写成大于 3 |
| T03 | 门槛 3，当前 5 颗星 | 门打开 | 待运行 | 待判定 | 是否误写成等于 3 |
| T04 | 同一颗星触发两次 | 只增加 1 分 | 待运行 | 待判定 | 消失/已收集状态或重复事件 |
| T05 | 开门后点击重开 | 分数 0，门关闭 | 待运行 | 待判定 | 是否重置所有状态 |

**无 AI 迁移题：** 把开门门槛改成 4；运行前给出 3、4、5 颗星的预期，再修改、验证并解释。允许看自己的知识卡，导师不指出要改的具体位置。

**加深题：** 设计两种星星，一种加 1 分、一种加 2 分。原来的“星星数量”与“分数”还有什么区别？哪些测试需要变化？

此表不预填实际结果。课堂是否通过以学员真实运行和解释为准。

## 表 4：AI 协作记录

| 字段 | 学员填写 |
| --- | --- |
| 我这一步要做什么 | 限定为一个功能或一个错误 |
| 我提供了哪些背景 | 当前规则、相关代码、报错、约束、验收条件 |
| AI 建议了什么 | 摘要即可，不复制整段私人对话 |
| 我采用／拒绝了什么 | 写出理由，不用“它说的应该对”代替 |
| 我实际修改了哪里 | 变量／条件／函数／界面；附版本标记 |
| 我运行了什么测试 | 正常情况、边界情况、修改可能影响的旧功能 |
| 这次是什么运行方式 | 真实模型协作 / 预设输出练习 / 协议模拟 / 真实协议调用；可多项记录 |
| 谁实际操作 | 学生 / 导师演示 / 师生共同完成；记录提供过的提示 |
| 结果与下一步 | 能证明完成了吗；哪里仍然不确定 |

### 一段可复用的请求模板

> 我在做【给谁用的作品】。现在【当前可运行状态】。这一步只要【一个变化】，暂时不要【范围外变化】。相关规则和代码是【资料】。请先说明计划，再给最小修改。我会用【输入与预期】检查。遇到缺少信息时先指出，不要猜测项目里不存在的文件。

模板用来帮助组织思路。评分看信息是否有用和验证是否成立，不看提示词长度或英文术语数量。

## 表 5：故障与版本记录

**问题：** ______　**当前版本：** ______　**上一可运行版本：** ______

1. 怎样从打开作品开始一步步复现？
2. 我希望发生什么，实际发生了什么？
3. 最先检查的一处是什么？为什么？
4. 这次只改变什么？
5. 原来的错误还会发生吗？哪些正常功能也要重测？
6. 修复版本怎样保存？如果修复失败，如何恢复？

探索组可用“原版／尝试版”文件和口述；进阶组保留清晰的 Git 提交与差异。不能只把 AI 自动检查点当成长期备份。

## 表 6：每四次课的家长反馈

**学员编号：** ______　**学习路径／阶段：** ______　**反馈范围：** 第 __–__ 次课

| 内容 | 具体记录 |
| --- | --- |
| 这次做了什么 | 一个可打开的作品或截图及其真实功能 |
| 新理解了什么 | 一个概念＋孩子自己的解释 |
| 能独立完成什么 | 一项未经提前演示答案的适龄任务 |
| 仍需要什么帮助 | 操作提示／概念提示／共同实现，明确是哪一种 |
| AI 与模板参与了什么 | 哪些由 AI、模板、导师协助，哪些由孩子判断和修改 |
| 下阶段目标 | 一个具体可观察目标，不写空泛“继续提升” |
| 家庭配合 | 可选短练习；不要求家长代改代码或额外购买工具 |

示例表达：“能够把开门条件从 3 分改为 4 分，并预测 3、4、5 分时的结果；重开后门仍保持打开的问题目前需要导师提醒检查状态。下一次练习完整重置两项状态。”这是记录写法示例，不是真实学员评价。

## 表 7：导师试讲与带课校准

建议用 20 分钟试讲＋10 分钟学生错误模拟＋10 分钟代码/积木修改。由两位评审分别记录；评分用于团队内部试运行，不作为已证实的教学质量指标。

| 维度 | 建议分值 | 高质量证据 |
| --- | --- | --- |
| 概念准确 | 25 | 能指出适龄简化的边界，例子与规则一致 |
| 适龄表达 | 20 | 术语有解释，能用不同表征说明同一概念 |
| 引导与诊断 | 25 | 先听思路，识别误解，逐级提示，不直接替做 |
| 技术验证 | 20 | 现场复现、修改、测试；能应对 AI 或环境失败 |
| 课堂与反馈 | 10 | 活动节奏合理，能留下学生个体学习证据 |

建议试讲总分达到 80/100，且概念准确至少 20/25、引导至少 18/25，再进入助教或共同授课观察。数值为初始内部阈值，试教后校准；学历与公司经历不直接换算为试讲得分。

出现关键概念错误、不做验证就断言 AI 正确、把替做记为学生完成时，先修订并复评，不由其他项高分抵消。

## 表 8：新技术进入课程的审核单

**候选技术／版本／官方来源／核查日期：** ______

| 判断 | 需要的证据 |
| --- | --- |
| 为什么教 | 对应哪个已有学习目标；解决什么真实任务 |
| 谁能用 | 年龄、地区、账号、机构方式；未核实时标待核查 |
| 学生缺什么前置 | 代码、数据、网络或工具调用知识 |
| 教师是否跑通过 | 起始环境、输入、输出、成本、失败与恢复 |
| 需要多少课时 | 删除或后移什么旧内容，不无上限加课 |
| 模拟与真实有什么差别 | 模拟能验证什么、不能证明什么 |
| 是否采用 | 纳入主线 / 进阶选修 / 继续观察，并写明理由 |

示例：MCP 连接进入进阶选修前，应先跑通“请求课程用的虚构资料列表→返回→检查空数据→拒绝未授权修改”。接入真实企业系统或个人账户不属于入门课必须任务。
