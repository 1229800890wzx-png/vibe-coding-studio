# 官网与小程序后端统一验收

日期：2026-09-14。分支：`codex/unified-backend`。服务基线 `9e67e2ed`，官网视觉快照 `00cd7b95`。所有新增业务写入使用恢复副本与 API 48081；未部署生产或发布微信小程序。

## 实际交付

| 原功能 | 统一后的入口与数据 |
| --- | --- |
| 官网服务介绍 | `website-offering/list`，同一数据库的 `edu_website_offering`，保留原标题/素材/阶段/大纲/排序 |
| 官网管理课程 | 后台 `/edu/website` 课程页签；新增、编辑、刷新、发布、撤下，revision 防覆盖 |
| 官网咨询 | 无需注册；`website-admission/create` 事务写原 CRM 线索、OWNER 权限及持久回执 |
| 官网咨询管理 | 原称呼、手机/邮箱、经验、兴趣、留言；NEW/CONTACTED/CLOSED 与 2000 字内部备注 |
| 招生工作台 | WEBSITE/MINIAPP 来源筛选；保留原 CRM 跟进、转交与数据范围，允许匿名线索无会员/孩子 |
| 正式教学与交易 | 原课程发布快照、会员、孩子、班期、报名、订单、支付、退款与学习服务继续使用 |
| 旧管理书签 | `/education`、`/education/manage` 跳转统一官网管理 |

官网当前真实基线只有 `/courses` 的服务锚点，没有 PR 另一套正式课程列表、分页或收费详情页面。本次保留视觉，公开正式课程 API 共用小程序发布来源，官网展示配置可选关联 courseId；未关联时提交通用咨询。

实际浏览器闭环覆盖官网预约、回执下载、后台新建/编辑/发布/撤下、顾问查看与保存咨询备注。复审修复了运营角色误发无权咨询请求、异步课程锚点定位、提交期间表单编辑、发布重试与只发布角色权限；正常页面未更换 CSS 或素材。

匿名接口记录持久授权版本与 trace，通用访问/异常日志不保留联系方式及请求正文。稳定业务错误码：`1090010001` 授权拒绝/版本过期，`1090010002` 内容冲突，`1090010003` 暂停受理，`1090010004` 限流。

运行中的原后端会继续写任务/访问日志，不能把原库总行数永久不变作为条件。整合工具只修改恢复副本；隔离回调与源库业务差异的复核记录保存在 `.runtime/unified/source-preservation-audit.json`。

首次交易回归的恢复库仍保留旧回调地址，产生两次到原 API 48080 的通知，分别被“交易订单不存在”“售后单不存在”拒绝。已修正恢复准备中的回调地址，并增加回归执行前检查。复核将原备份恢复到另一新审计库并逐行比较：177/182 表完全一致，所有支付、交易、教育和 CRM 业务表无新增、删除或字段变化；仅3张Quartz运行状态表和任务/访问日志发生变化。

生产渠道、域名、机构负责人及正式课程内容需要真实配置。交付的是已实现、已本地验收的统一系统及部署资产，不是生产上线声明。原始测试报告含合成联系方式或环境细节，保留在忽略目录，公开仓库仅存本说明。
